# ERP 필요 기능 조사 및 설계 계획서

> 목적: 상용 ERP가 실제로 제공하는 **기능**을 조사해 "ERP라면 반드시 있어야 하는 기능"의 목록을 만들고, 우리 제품의 기능 범위와 모듈 설계에 반영한다.
> 근거: [01_ERP_기술조사.md](01_ERP_기술조사.md)(기술·아키텍처), [02_ERP_설계계획서.md](02_ERP_설계계획서.md)(스택·아키텍처·로드맵). 본 문서는 그 사이의 **기능 요구사항** 계층을 채운다.

## 1. 상용 ERP 기능 맵

제품마다 명칭은 다르지만 기능 분류는 거의 일치한다. SAP 모듈명(FI·CO·MM·SD·PP·HR)이 사실상의 업계 표준 분류로 쓰인다 (국내 KYS도 SD/MM/PP/IV/QM/FI/HR 표기를 그대로 차용).

| 기능 영역 | 글로벌 상용 | 국내 상용 | 우리 범위 |
|---|---|---|---|
| 기준정보(MDM)·플랫폼 | 전 제품 필수 | 전 제품 필수 | **P0** |
| 회계 FI (전표·원장·결산·재무제표·부가세) | 전 제품 핵심 | 전 제품 핵심 (국내는 세무 연동까지) | **P0** |
| 영업/판매 SD (견적→수주→출고→매출→수금) | 전 제품 | 전 제품 | **P0** |
| 구매 MM (요청→발주→입고→매입→지급) | 전 제품 | 전 제품 | **P0** |
| 재고 IV (입출고·수불부·실사·창고) | 전 제품 | 전 제품 | **P0** |
| 전자세금계산서·세무 신고 | 국가별 현지화 패키지 | **국내 전 제품 필수** (홈택스 연동) | **P0** |
| 채권/채무·자금 | 전 제품 | 전 제품 (자금일보·어음 포함) | **P1** |
| 생산 PP (BOM·작업지시·MRP·실적) | 제조 패키지 | 제조형 패키지 (KYS는 Professional부터) | **P1** |
| 원가 CO | 중견 이상 | 중견 이상 (영림원·Amaranth) | **P2** |
| 인사/급여 HR (근태·급여·원천세·4대보험·연말정산) | 별도 HCM 연동 많음 | **국내는 ERP 내장이 일반적** | **P2** (분개 인터페이스는 선확보) |
| 고정자산 | 전 제품 | 전 제품 | **P2** |
| 품질 QM | 대형/제조 패키지 | 제조형 일부 | 후순위 (MES 연동으로 커버) |
| CRM/AS 서비스 | 별도 제품 연동 | 이카운트·더존 내장 일부 | 후순위 |
| 수출입/프로젝트/건설 등 업종 특화 | 업종 패키지 | 업종 패키지 (얼마에요 수출입·건설) | 제외 (업종 확장 시) |
| POS·쇼핑몰 연동 | Odoo/소매 패키지 | 도소매 패키지 | 제외 |
| 대시보드/리포트·BI | 전 제품 | 전 제품 (분석 메뉴 필수) | **P2** |
| 커스터마이징·OpenAPI·워크플로 | 상용화 필수 | 설정 기반 커스터마이징 | **P1**부터 점진 |

**결론 1**: P0(기준정보·영업·구매·재고·회계·세금계산서)는 어떤 제품도 빼지 않는 최소 기능 집합 = MVP.

**결론 2**: 국내 제품과 글로벌의 큰 차이는 ① 급여·세무가 제품 안에 들어오는 정도, ② 엑셀 수준 그리드 UX, ③ 세금계산서를 상품으로 팔 정도의 비중.

## 2. 모듈별 기능 인벤토리

## 3. 조사에서 뽑은 기능 패턴 (설계 반영)

1. **문서 흐름의 단일 패턴**: 판매·구매·반품이 전부 "요청→주문→입출고→인보이스→결제"의 대칭 구조 → 하나의 문서 프레임워크(상태머신+채번+분개 규칙+출력물)로 전 모듈을 구현 (02 §3, §4.2 확정).
2. **확정 = 세무 이벤트**: 매출/매입 확정이 세금계산서 발행과 자동분개를 동시에 유발 → "확정"을 상태머신의 최종 단계로 두고 사후 이벤트를 아웃박스로 발행.
3. **증빙 수집 자동화가 국내 경쟁력**: 더존의 '스마트 증빙'(카드·현금영수증·세금계산서 자동수집→자동분개)이 실무 시간을 줄이는 핵심 → P1에 매입 수집·자동분개를 명시.
4. **조회성 메뉴가 기능의 절반**: 요약·연령·이력·현황 화면이 수십 개 → 입력 화면과 별개로 "조회 뷰"를 데이터 모델 설계 때부터 고려 (집계 뷰·인덱스 전략).
5. **연도별 규정 데이터**: 급여 요율·세액표·신고서식이 매년 바뀜 → 코드가 아닌 `annual_policy` 마스터 데이터 관리 + 갱신 절차를 운영에 포함 (02 §7 확정).
6. **출력물 = 업무의 일부**: 거래명세서·견적서·발주서가 없으면 판매 불가 → 인쇄 양식을 기능 범위로 (P0 기본 서식, P1 고객 편집).

## 4. 우리 제품 기능 범위 (확정안)

### 4.1 MVP (파일럿 도입 가능 범위)

- **기준정보·플랫폼**: 마스터 일체, RBAC+데이터 권한, 채번·상태·감사로그, 엑셀 업/다운, 기본 출력물
- **영업**: 견적→수주→출고→매출→세금계산서(정/수정·전송추적)→거래명세서
- **구매**: 발주→입고(검수)→매입→매입계산서 수집 연동
- **재고**: 입출고·이동·조정·실사·수불부·현재고 (이동평균)
- **회계**: 자동분개·전표·원장·시산표·재무제표 2표·기간마감·부가세 자료

### 4.2 1차 확장 (상용 출시까지)

- 채권/채무·자금 (수금·지급·자금일보·통장 연동), 매입 증빙 자동수집
- 생산: BOM·작업지시·불출입고·기초 MRP
- 확장: 커스텀필드·인쇄양식·승인규칙·OpenAPI·그룹웨어 SSO/결재 연동
- 안전재고·여신한도·바코드 입출고

### 4.3 2차 확장

- 인사/급여(연도별 기준 데이터)·고정자산·원가·예산·관리회계·분석 리포트·모바일

### 4.4 제외 (재검토 조건: 업종 확장)

- 수출입·건설/서비스 업종 특화, POS·쇼핑몰, LOT/시리얼(식품·의료 진출 시), 고급 BI

## 5. 설계에의 반영

| 조사 결과 | 반영 위치 (02 문서) |
|---|---|
| 전 모듈 동일 문서 흐름 | §3 모듈러 모놀리스 + §4.2 문서 공통 프레임워크 → core에 `document` 기반 클래스 |
| 확정→자동분개+세금계산서 동시 유발 | §4.1 분개 규칙 + 아웃박스 이벤트 |
| 국내 세무가 1급 기능 | §7 한국 연동 → `tax-billing`(세금계산서 어댑터) 모듈을 P0로 승격 |
| 증빙 수집 자동화 | §7 매입 수집 → P1으로 명시 (수집→초안→확정 파이프라인) |
| 조회성 메뉴 다수 | §9 성능 → 집계 뷰·보조장부를 뷰/캐시로 제공, 전표 라인에 (tenant, 기간, 계정) 인덱스 |
| 연도별 규정 데이터 | §7 `annual_policy` 확정 |
| 업종 특화 제외 | §1 범위 → "업종 패키지"는 테넌트별 기능 플래그로 후순위 대응 가능하게 코어에 훅만 |

## 6. 결정 필요 사항 (02 §10 연동)

| # | 항목 | 기능 조사가 주는 힌트 | 상태 |
|---|---|---|---|
| 1 | 기술 스택 | 기능 목록과 무관 — 02 §10-1 그대로 | 미결 |
| 2 | 제품 형태 (SaaS vs 온프레) | 세금계산서 인증서 보관 방식·연계 사업자 계약이 달라짐 | 미결 |
| 3 | 타깃 업종 | **제조 선택 시 생산 P1 필수**(BOM·작업지시 없이 제조 고객 불가), 도소매면 P0만으로 판매 가능 | 미결 — 파일럿 고객에 따라 결정 |
| 4 | 급여 시점 | 국내 경쟁 제품은 전부 내장 — 장기 필수, P2 유지하되 분개 인터페이스 선확보 | 부분 결정 |
| 5 | 세금계산서 연계 사업자 | 팝빌/바로빌/스마트빌 비교 필요 — **어댑터 패턴 확정** | 설계 결정 완료, 사업자 미선정 |
| 6 | MES 경계 | 조사상 국내 ERP의 생산 모듈은 수불·원가 중심 — 작업지시·실적은 MES 소유가 자연스러움 | 방향 확정 |
| 7 | 오픈소스 활용 | 기능 참고만, 포크 금지 | 결정 완료 |
| 8 | **신규** — CRM/AS·모바일 범위 | 국내 제품도 2순위 기능 → 제외 확정 여부 | 미결 |
