# 01. 기준정보 모듈 설계 계획서

> 목적: 전 모듈이 참조하는 마스터 데이터(조직·거래처·품목·계정·창고·코드)의 모델과 관리 규칙 정의.
> 우선순위: P0. 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: 회사·사업장, 부서·사원, 거래처, 품목·품목그룹·BOM, 창고, 계정과목, 자금 마스터(계좌·카드·어음), 공통코드, 환율(P1)
- 제외: 문서·거래 데이터(각 모듈 소유), 인사 상세(P2 인사 모듈)

## 2. 화면/메뉴

| 메뉴 | 기능 | 비고 |

| 회사·사업장 | 등록·수정·사업자정보(업태·종목·세무서) | 사업장 = 부가세 신고 단위 → 1급 객체 |
| 부서·사원 | 조직 트리, 사원-사용자계정 연결, 담당자 지정 | |
| 거래처 | 등록·엑셀 일괄·사업자 상태조회·여신한도·사용중지·변경이력 | |
| 품목 | 그룹 트리, 단위, 과세/면세/영세, 세트품목, 거래처별 품목(P1), 바코드(P1) | |
| BOM | 구성품목 정/역전개, 버전·유효기간 | 재고·생산 참조 (P1 활성) |

| 환율·통화 | 통화 마스터, 일자별 환율 | P1 |

## 3. 데이터 모델

### 3.1 조직

| 테이블 | 주요 컬럼 |
|---|---|
| `company` | id, tenant_id, name, 대표자, corp_no(법인번호), addr |
| `business_site` | id, company_id, biz_no(사업자등록번호·유일), name, 업태·종목, addr, tax_office |
| `department` | id, company_id, parent_id, code, name, sort |
| `employee` | id, dept_id, emp_no, name, user_id(OIDC 계정 링크), title, is_active |

### 3.2 거래처·품목

| 테이블 | 주요 컬럼 |
|---|---|
| `partner` | id, type(customer/vendor/both), biz_no, name, ceo, addr, 담당자/연락처, credit_limit, payment_term, vat_id(과세유형), is_active, custom_fields(JSONB) |
| `item` | id, code, name, spec, unit, item_group_id, tax_type(과세/면세/영세), sale_price, purchase_price, safety_stock, barcode?, is_active, custom_fields |
| `item_group` | id, parent_id, code, name — 트리 |
| `item_partner` | 거래처별 품목코드 매핑 — `partner_price`(영업 모듈)로 통합. 단가 이력 컬럼(`partner_item_code`, `partner_item_name`)을 포함하므로 본 테이블은 두지 않음 |
| `bom` / `bom_line` | parent_item_id, ver, effective_from/to, is_active / seq, child_item_id, qty, loss_rate |

### 3.3 회계·창고·코드

| 테이블 | 주요 컬럼 |
|---|---|
| `account` | id, code(유일), name, parent_id, acct_type(자산/부채/자본/수익/비용), aux_partner/dept/project 플래그, cash_flow_item?, is_active |
| `account_template` | standard(k_gaap/k_ifrs), json — 신규 테넌트 계정과목 시드 |
| `warehouse` | id, site_id, parent_id, code, name, wh_type(정상/불량/외주/가상), is_active |
| `bank_account` / `credit_card` / `bill_type` | 자금 마스터 — 은행, 계좌번호(암호화), 용도 |
| `code_group` / `code` | group_id, code, name, sort, is_active |
| `exchange_rate` | currency, date, rate (P1) |

## 4. 비즈니스 규칙

- 마스터는 **삭제 금지** — `is_active=false`(사용중지). 사용중지는 신규 문서 라인 선택 차단, 기존 문서 조회는 정상.
- `partner.biz_no` 테넌트 내 유일 + 등록·발행 시 국세청 **사업자 상태조회**로 휴·폐업 경고.
- 계정과목: 자식 있는 계정은 전표 불가(말단만), 보조부 플래그 있는 계정은 해당 보조대상 필수.
- `code` 변경은 미사용 시만; 사용 중이면 신규 코드 추가 + 기존 사용중지.
- 주민번호·계좌번호 등 고유식별정보는 컬럼 암호화(AES-256-GCM) + 조회 로그.

## 5. API 스케치

```
GET/POST   /mdm/partners                PATCH /mdm/partners/{id}
POST       /mdm/partners/{id}:biz-check         # 국세청 상태조회
GET/POST   /mdm/items                   PATCH /mdm/items/{id}
GET/POST   /mdm/accounts                PATCH /mdm/accounts/{id}
POST       /mdm/accounts:import-template        # 기준 템플릿 적용
GET/POST   /mdm/warehouses              /mdm/boms  /mdm/codes  /mdm/companies
공통: :activate / :deactivate, :import(엑셀), :export
```

## 6. 연동·이벤트

- 발행: `partner.deactivated`, `item.changed`(소비자 없음 — 스냅샷으로 격리)
- 구독: 사업자 상태조회 API(공공데이터), 주소 API(도로명주소)

## 7. 수용 기준

- [ ] 마스터 CRUD + 엑셀 일괄등록/다운로드
- [ ] 사용중지 항목이 신규 문서에서 선택 불가, 기존 문서 정상 표시
- [ ] 사업자 상태조회 연동, 중복 사업자번호 차단
- [ ] 계정과목 템플릿으로 신규 테넌트 계정 시드
- [ ] 변경 감사 로그(전/후) 확인

## 8. 후순위·미결

- 품목 이미지/첨부, 거래처별 단가 계약(단가표), 주소 2단(본점/지점) — P1
- 결정 필요: 마스터 변경이력을 별도 버전 테이블로 둘지, 감사 로그로 충분한지 — **감사 로그로 통일 권장**.
