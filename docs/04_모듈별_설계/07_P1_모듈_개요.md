# 07. P1+ 모듈 개요

> 목적: P1 이후 모듈의 범위·경계·설계 방향을 개요 수준으로 고정한다. 상세 설계는 해당 단계 착수 시 모듈별 문서로 분리.
> 근거: [03_ERP_필요기능_설계계획서.md](../03_ERP_필요기능_설계계획서.md) §4.2~4.3.

---

## 1. 채권/채무·자금 (P1)

- **범위**: 미수·미지급 잔액, 수금·지급 처리, 자금일보·자금계획, 통장 입출내역 연동(오픈뱅킹/수집API), 어음·수표 관리
- **핵심 모델**: `receipt`/`payment` + `*_allocation`(인보이스 상계), `bank_transaction`(수집 내역→수금/지급 매칭), `cash_plan`
- **설계 방향**: 영업·구매와 같은 문서 프레임워크. 통장 수집 내역은 매입 세금계산서 수집과 같은 '수집→매칭' 패턴 재사용.
- **연동**: 매출·매입 posted → 채권/채무 생성, 수금·지급 posted → 분개 + 상계

## 2. 생산 (P1 — 제조업 타깃 시)

- **범위**: BOM(기준정보 소유), 작업지시, 자재소요량 산출(기초 MRP), 자재불출·제품입고(수불 연동), 외주(P2)
- **경계**: 작업지시·공정실적·불량은 **MES(PFMES) 소유** — ERP는 수불·원가·발주 제안까지. 연동은 API/이벤트.
- **핵심 모델**: `work_order`(ERP측 수불 단위), `bom` 전개 → 소요량, `mrp_run` 결과 → 발주 제안 리스트

## 3. 확장 플랫폼 (P1부터 점진 — 상용화 생명줄)

- **커스텀 필드**: `custom_field_def`(entity, field, type, meta) + 라인/헤더 `custom_fields` JSONB → 폼 메타데이터로 UI 자동 렌더
- **인쇄 양식**: `print_template` 고객별 템플릿(HTML→PDF), 기본 서식 제공(견적서·발주서·거래명세서·세금계산서)
- **승인·채번 규칙**: 테넌트 설정 (승인 라인, 채번 패턴)
- **Open API·웹훅**: 테넌트별 API 키 + 이벤트 웹훅 구독
- **원칙**: 고객 코드는 별도 포크 금지 — 커스텀 필드/양식/규칙/훅으로 흡수 (Clean Core)

## 4. 인사/급여 (P2)

- **범위**: 인사카드·발령, 근태(그룹웨어 소유·연동), 급여 계산(기본급·수당·공제·상여), 퇴직정산, 원천세·4대보험 신고 자료, 연말정산
- **핵심**: 요율·간이세액표·신고서식은 매년 변경 → `annual_policy`(연도·항목별 JSON 기준 데이터)로 관리, 코드 변경 없이 갱신
- **연동**: 급여 posted → 회계 자동분개 (인터페이스는 P0에 확보)

## 5. 고정자산 (P2)

- 취득→감가상각(정액/정률, 월 단위)→처분, 감가상각 자동분개, 자산 대장

## 6. 대시보드·리포트 (P1 기본 ~ P2)

- 기본 대시보드: 월매출·매입·미수·미지급·재고 KPI 카드 (P1)
- 분석 리포트: 거래처/품목/기간 매출분석, 채권연령, 손익분석, 생산실적 — 조회성 뷰 위에 구축
- 사용자 정의 리포트: 후순위(필터+컬럼 선택 저장)

## 7. 제외 모듈 (재검토 조건)

- 수출입(P/O·L/C·HS코드), 건설/서비스 업종 특화, POS·쇼핑몰 연동, LOT/시리얼(식품·의료), 예산통제 심화, BI 도구 연동
- 설계 방침: 업종 특화는 테넌트 기능 플래그로 나중에 켤 수 있게 코어에 훅만 유지
