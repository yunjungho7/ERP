# 05. 회계 모듈 설계 계획서

> 목적: 모든 거래가 모이는 단일 원장 — 자동분개(분개규칙)·수기전표·장부·재무제표·부가세·기간마감. 정확성 최우선 모듈.
> 우선순위: P0. 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: 분개규칙 엔진, 전표 입력·승인, 총계정원장·계정별원장·보조부, 일·월계표·시산표, 재무제표, 부가세 신고 자료, 기간 마감, 역분개, 거래 통화 기록(통화·환율 마스터는 P1)
- 제외: 예산·관리회계 심화(P1~P2), 외화평가·환산 결산(P2), 원가회계(P2)

## 2. 화면/메뉴

| 메뉴 | 기능 |
|---|---|
| 전표 입력 | 수기 전표(일반·대체), 차대 입력 균형 검증 |
| 전표 조회·승인 | 기간/계정/상태별 목록, 확정(confirm)→게시(post) 분리 |
| 자동분개 관리 | posting_rule 목록·수정, 이벤트→계정 매핑, 생성 결과 검토 |
| 총계정원장 | 계정별 차·대·잔 |
| 계정별원장·보조부 | 계정×보조대상(거래처/부서/프로젝트) 라인 원장 |
| 일계표·월계표·시산표 | 기간별 차대 합계 검증 |
| 재무제표 | 재무상태표·손익계산서 (제조원가명세서 P1) |
| 부가세 신고자료 | 매출·매입처별 합계표, 신고서식 매핑, 홈택스 파일 |
| 기간마감 | 회계기간 마감·재개, 마감 후 거래 차단 |
| 분개규칙 설정 | 이벤트→차/대 계정 매핑 테이블 편집 |

## 3. 데이터 모델

| 테이블 | 주요 컬럼 |
|---|---|
| `journal_entry` | id, doc_no, entry_date, site_id, memo, status, source_type, source_id, posted_at, posted_by, reversal_of? |
| `journal_entry_line` | entry_id, seq, dc(d/c), account_id, partner_id?, dept_id?, project_id?, memo, amount NUMERIC(18,2), currency?, fx_rate? |
| `posting_rule` | id, event_type, condition(JSON: 품목유형·거래처유형·창고유형 등), dc, account_id, amount_expr(supply/vat/total), priority |
| `fiscal_period` | site_id, close_level(company/site — 법인 결산 마감과 사업장 부가세 마감을 분리), year, period, closed_at, closed_by |
| `account_balance`(조회용 뷰/테이블) | account_id, period, debit, credit — 집계 캐시 |
| `aux_ledger` | 보조부 조회 뷰 — account×partner/dept/project 집계 |

## 4. 불변식 (회귀 테스트 필수)

1. `posted` 전표는 Σ차변 = Σ대변 — 트랜잭션 내 검증, 불일치 시 게시 거부.
2. `posted` 전표·라인 UPDATE 금지 — 정정은 `reversal_of` 참조의 역분개 전표(음수 동일 라인)만.
3. 마감된 `fiscal_period`에는 entry_date 해당 전표 생성·게시·역분개 차단.
4. 말단 계정만 사용 가능, 보조부 필수 계정(`aux_partner` 등)은 대상 누락 차단.
5. `source` 참조 유일 — 한 문서 이벤트가 중복 분개 생성 불가 (멱등키).

## 5. 처리 흐름

### 5.1 자동분개
```
모듈 이벤트(posted) → outbox → posting_rule 조회(우선순위 순)
  → journal_entry(draft→posted 즉시) 생성 → source_type/id로 역추적
```
- 규칙 없음/계정 미설정 시 전표 생성 안 하고 `pending` 큐 + 알림 — 설정 보강 후 재생성.
- amount_expr: `supply`(공급가), `vat`(세액), `total`, `cost` 등 변수 — 라인 단위 전개(품목유형별 계정 분기 가능).

### 5.2 수기 전표
입력(draft) → 차대 균형 검증 → confirm → post. 대량 입력은 엑셀 업로드 지원.

### 5.3 조회 계층
- 원장·보조부: `journal_entry_line` 실시간 조회 — (tenant, period, account) 인덱스.
- 시산표·재무제표: `account_balance` 집계 캐시(전표 post 시 갱신 또는 주기 재계산) → p95 < 1s 목표.
- 부가세: 사업장 단위로 매출(과세/면세/영세)·매입 유형별 합계 → 신고서식 필드 매핑.

## 6. API 스케치

```
/accounting/journal-entries          GET/POST, :confirm :post :reverse
/accounting/posting-rules            GET/POST/PATCH
/accounting/ledgers/general          GET ?account=&period=
/accounting/ledgers/auxiliary        GET ?account=&aux_type=&aux_id=
/accounting/reports/trial-balance    GET ?period=
/accounting/reports/financial        GET ?type=bs|is&period=
/accounting/vat                      GET ?site=&quarter= (부가세 자료)
/accounting/periods                  GET, :close :reopen
```

## 7. 연동·이벤트

- 구독: `sales_invoice.posted`, `purchase_invoice.posted`, `receipt.posted`, `payment.posted`, `stock.adjust/count.posted`, (P2) `payroll_run.posted`, `depreciation_run.posted`, `asset_disposal.posted`
- 발행: `journal_entry.posted`(관측용), `fiscal_period.closed` → 알림

## 8. 수용 기준

- [ ] 각 모듈 posted 이벤트가 posting_rule에 따라 정확한 차·대 전표 생성
- [ ] 수기 전표 차대 불일치 게시 불가
- [ ] 역분개: 원본·정정 전표 상호 참조, 잔액 정확
- [ ] 마감 기간 차단, 마감 후 재개는 권한자만
- [ ] 시산표 차대 일치, 재무제표 합계 = 원장 합계
- [ ] 부가세 매출처별 합계표 = 매출 전표 합계와 일치

## 9. 후순위·미결

- 관리회계(코스트센터·프로젝트 손익), 예산 통제, 외화평가·환산 결산, 자금일보 연동, 결산 조정(충당금 등) — P1~P2
- 미결: `account_balance` 실시간 갱신(정합성 ↑) vs 배치 재계산(단순) — 전표 post 트랜잭션 내 갱신 권장.
