# 07. 자금 모듈 설계 계획서

> 목적: 채권(미수)·채무(미지급)와 자금 흐름 관리 — 수금·지급 처리, 통장 입출내역 연동, 자금일보·자금계획, 어음 관리.
> 우선순위: P1. 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: 거래처별 미수·미지급 잔액, 수금·지급 문서, 통장 입출내역 수집→매칭, 자금일보·자금계획, 어음·수표
- 제외: 자동 이체·펌뱅킹 실행(P2), 자금시재 심화·자금부문 결산(P2), 외화 자금(P2)

## 2. 화면/메뉴

| 메뉴 | 기능 |
|---|---|
| 미수 현황 | 거래처별 채권 잔액·연령, 인보이스별 미수 상세 |
| 미지급 현황 | 거래처별 채무 잔액·연령 |
| 수금 등록 | 수금 입력 + 미수 상계 (부분 수금 허용) |
| 지급 등록·결의 | 지급 입력 + 미지급 상계, 지급 결의(승인) 흐름 |
| 통장 입출내역 | 은행 내역 수집 → 수금·지급 문서 자동/수기 매칭 |
| 자금일보·자금계획 | 일별 입출·잔액, 예정 입출금 캘린더 |
| 어음 관리 | 받을어음/지급어음 등록·만기·부도 처리 |

## 3. 데이터 모델

| 테이블 | 주요 컬럼 |
|---|---|
| `receipt` + `receipt_allocation` | **소유권은 자금 모듈** (영업·구매는 조회·링크만) — doc_no, partner_id, method, amount / invoice_id, alloc_amount |
| `payment` + `payment_allocation` | 동형 |
| `bank_transaction` | bank_account_id, occurred_at, type(in/out), amount, counter_name, memo, matched_source_type/id, status(unmatched→matched) |
| `cash_plan` | plan_date, type(수금예정/지급예정/기타), partner_id?, amount, source_type/id |
| `note_receivable` / `note_payable` | 어음 — no, partner, amount, issue_date, due_date, status(보유→결제/할인/부도) |
| `bank_account` | 기준정보 소유 — 자금 계정·은행·계좌 |

## 4. 처리 규칙

- 상계(allocation)는 인보이스 단위, `alloc_amount ≤ 미수/미지급 잔액`. 부분 상계·여러 인보이스 분할 허용 (00 §7-4).
- 연령 분석 기준일은 인보이스의 `due_date`(결제기한 스냅샷) — 영업·구매 모듈이 확정 시점에 기록.
- 통장 내역 수집(오픈뱅킹/연계 API) → 금액·거래처명·일자로 수금/지급 후보 자동 제안, 확정은 사용자.
- 어음: 수금·지급 method가 '어음'이면 note 문서 자동 생성 → 만기 결제 시 잔액 반영, 부도 시 채권 복원.
- 분개 (posting_rule 대상 이벤트):

| 이벤트 | 차변 | 대변 |
|---|---|---|
| receipt.posted | 보통예금/받을어음 | 외상매출금 |
| payment.posted | 외상매입금 | 보통예금/지급어음 |
| note_receivable.due_paid | 보통예금 | 받을어음 |
| note_receivable.dishonored | 부도어음 | 받을어음 |

## 5. API 스케치

```
/finance/receivables       GET ?partner= (미수 현황·연령)
/finance/payables          GET (미지급 현황)
/finance/receipts          GET/POST, :confirm :post :cancel
/finance/payments          GET/POST, :confirm :post :cancel, :approve (지급 결의)
/finance/bank-transactions GET, POST :match {id}
/finance/cash-daily        GET ?date=  (자금일보)
/finance/cash-plan         GET/POST
/finance/notes             GET/POST, :pay :discount :dishonor
```

## 6. 연동·이벤트

- 구독: `sales_invoice.posted`→채권(미수) 생성, `purchase_invoice.posted`→채무 생성, `bank_transaction.collected`→매칭 제안
- 발행: `receipt.posted`, `payment.posted` → 회계 분개 + 채권/채무 상계, `cash_plan.*` → 자금계획 갱신

## 7. 수용 기준

- [ ] 매출·매입 posted 시 미수·미지급 잔액 자동 반영
- [ ] 수금·지급이 인보이스 단위 상계되어 잔액 정확
- [ ] 통장 내역 수집→매칭으로 수금 문서 자동 제안
- [ ] 어음 등록·만기·부도 상태 추적, 부도 시 채권 복원
- [ ] 자금일보 잔액 = 통장 잔액과 대사 가능

## 8. 후순위·미결

- 자동 이체(지급 파일/펌뱅킹), 예적금·대출 관리, 자금부문 예산 — P2
- 미결: 은행 연동 방식 — 오픈뱅킹 API vs 연계 사업자 수집 서비스 (세금계산서 사업자와 동일 사가 내역 제공 시 그쪽이 간결).
