# 04. 재고 모듈 설계 계획서

> 목적: 모든 입출고의 기록 원장 — append-only 수불부 + 현재고 스냅샷 + 평가(이동평균). 영업·구매·생산의 수량 원천.
> 우선순위: P0. 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: 입출고(유형별), 창고이동, 재고조정, 재고실사, 수불부/현재고 조회, 안전재고(P1), 평가(이동평균 기본)
- 제외: LOT/시리얼·유효기한(P2), 바코드 입출고(P1~P2), FIFO·표준원가(P2)

## 2. 화면/메뉴

| 메뉴 | 기능 |
|---|---|
| 입출고 등록 | 수기 입고·출고(유형: 정상/반품/샘플/불량/기타) — 문서 기반 외의 조정 입출고 |
| 창고이동 | 창고 간 이동(이동확정 시 재고 반영) |
| 재고조정 | 수량·원가 조정(사유 필수) |
| 재고실사 | 기준일 장부수량 vs 실사수량 → 차이 조정 일괄 처리 |
| 수불부 | 품목별·창고별·기간별 입출고 내역+잔량 |
| 현재고 조회 | 품목별/창고별/그룹별 재고, 가용량(재고-예약) |
| 안전재고 | 품목별 안전재고, 미달 알림 (P1) |

## 3. 데이터 모델

| 테이블 | 주요 컬럼 |
|---|---|
| `stock_ledger` | id, occurred_at, item_id, warehouse_id, io_type(in/out), reason(normal/return/sample/defect/move/adjust/count), qty, unit_cost, source_type, source_id, posted_by — **append-only** |
| `stock_balance` | (item_id, warehouse_id) PK, qty, avg_cost, updated_at |
| `stock_move` + `_line` | doc_no, from_wh, to_wh, status(draft→confirmed) / item, qty |
| `stock_adjust` + `_line` | doc_no, reason, status / item, wh, qty_diff, cost_diff |
| `stock_count` + `_line` | doc_no, count_date, wh, status / item, book_qty, actual_qty, diff → posted 시 adjust 생성 |
| `safety_stock` | item_id, warehouse_id, min_qty (P1) |

## 4. 처리 규칙

### 4.1 수불 기록
- 모든 입출고는 문서 확정 트랜잭션 안에서 재고 공개 서비스 `stock.apply(source_type, source_id, lines[])`를 **동기 호출**하여 `stock_ledger` insert + `stock_balance` 갱신을 한 트랜잭션으로 처리한다 (00 §2 동기 예외).
- 멱등키 `(source_type, source_id)`로 중복 적용 방지 — 재호출 시 기존 적용분을 반환.
- `stock_ledger`는 UPDATE/DELETE 없음 — 취소는 반대 방향 ledger 행 추가(`source`로 역추적).
- 출고 시 `(item_id, warehouse_id)` 행 잠금(`FOR UPDATE`) → 잔량 검사 후 차감. 음수재고 허용은 테넌트 플래그.

### 4.2 평가 (이동평균)
- 입고: `avg_cost = (기존수량×기존단가 + 입고수량×입고단가) / (기존수량+입고수량)` — 수량 0이면 입고단가.
- **음수재고 허용 테넌트**: 수량이 0 이하인 상태에서 입고 시 `avg_cost`는 입고단가로 리셋(음수 구간 단가 왜곡 방지). 음수 상태에서의 출고는 리셋 전 `avg_cost`를 유지.
- 출고·이동: 현재 `avg_cost`로 기록(재평가 없음). 역처리는 원 ledger 단가로 복원.
- FIFO는 수불부 순서 기반 별도 계산(P2), 표준원가는 평가 정책 필드 추가(P2).

### 4.3 창고이동·조정·실사
- 이동: `confirmed` 시 out(from)+in(to) ledger 2행 동시 생성.
- 조정: 수량 조정(`qty_diff`)과 원가 조정(`cost_diff`) 분리 — 원가만 변경은 `reason=cost_adj`.
- 실사: `posted` 시 diff 라인별 `stock_adjust` 자동 생성 → 분개 이벤트.

### 4.4 분개 연동 (테넌트 설정)
- 기본: `stock.adjust/count.posted`만 분개 (재고자산 차대). 전 유형 분개는 옵션 — 00 §7-2.

## 5. API 스케치

```
/stock/ledgers        GET (수불부 조회 — 필터: 품목·창고·기간·유형)
/stock/balances       GET (현재고 — 품목·창고·그룹별 집계)
/stock/moves          창고이동
/stock/adjustments    재고조정
/stock/counts         실사
POST /stock/counts/{id}:apply-diff              # 차이 일괄 조정
GET  /stock/availability?item=&warehouse=       # 가용량
```

## 6. 연동·이벤트

- 수불 반영: 문서 확정 트랜잭션 내 **동기 호출** — `shipment.confirmed`(출고), `goods_receipt.confirmed`(입고), `sales_return.posted`(반품입고), `purchase_return.posted`(반품출고), `material_issue.confirmed`(불출), `production_receipt.confirmed`(입고) (P1). 아웃박스 이벤트를 경유하지 않음 (00 §2).
- 발행(비동기): `stock.adjust.posted`, `stock.count.posted` → 회계 분개, `stock.low`(안전재고 미달) → 알림 (P1)

## 7. 검증·불변식

- `stock_ledger` 합계 = `stock_balance` — 일일 대사 잡으로 검증, 불일치 알림.
- 동시 출고 경쟁에서 음수재고 미발생 (동시성 테스트 필수).
- ledger 삽입 실패 시 문서 확정 롤백 — 부분 기록 없음.

## 8. 수용 기준

- [ ] 수불부가 모든 입출고 원본까지 추적(`source_type/id`로 문서 드릴다운)
- [ ] 현재고·가용량 조회가 문서 확정과 동시에 정확 반영
- [ ] 동시 출고 테스트에서 음수재고 0
- [ ] 실사 → 차이 조정 → 분개 연결
- [ ] ledger-row 수불부 합계와 balance 일치 대사 통과

## 9. 후순위·미결

- 바코드 입출고·라벨, 창고 보관장소(로케이션) 세분화, 예약재고(수주 할당) — P1~P2 (바코드 입출고는 P1)
- 미결: 가용량 정의(재고-수주할당 예약)를 P0에 포함할지 — 기본은 '재고 그대로', 예약 개념은 P1로.
