# 12. 대시보드·리포트 모듈 설계 계획서

> 목적: 경영 KPI 대시보드 + 분석 리포트 — 전부 읽기 전용 조회 계층으로, 트랜잭션 데이터는 건드리지 않는다.
> 우선순위: P1(기본 대시보드) ~ P2(분석·사용자 정의). 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: KPI 대시보드(월매출·매입·미수·미지급·재고·수주/발주 현황), 분석 리포트(매출·매입·재고·채권연령·손익), 저장 리포트
- 제외: BI 도구 연동(Tableau 등), 임의 쿼리 빌더, 예측 분석 — P2 후순위~제외

## 2. 화면/메뉴

| 메뉴 | 기능 |
|---|---|
| 경영 대시보드 | KPI 카드 + 추이 차트 — 권한별 위젯 구성 |
| 매출·매입 분석 | 거래처/품목/기간/담당별 집계·순위 |
| 재고 분석 | 현재고·회전율·장기체재고 |
| 채권·채무 분석 | 연령별 미수·미지급 |
| 손익·생산 분석 | 기간 손익 추이, 생산 실적 (생산 모듈 도입 후) |
| 저장 리포트 | 필터+컬럼+정렬 저장·공유 |

## 3. 데이터 모델

| 테이블 | 주요 컬럼 |
|---|---|
| `report_def` | name, entity, filters JSON, columns JSON, sort, shared, owner |
| `dashboard_widget` | user/role, widget_type, position, config JSON |
| 조회 뷰들 | `v_sales_summary`, `v_purchase_summary`, `v_receivable_aging` 등 — 쿼리 레이어, 테이블 아님 |

## 4. 처리 규칙

- 전부 읽기 전용 — 문서/장부 쓰기 없음.
- 실시간 조회(소규모) 기본 + 대량 집계는 집계 뷰/캐시로 보완. 별도 DW·OLAP는 도입 안 함.
- 성능 목표: 대시보드 초기 로드 p95 < 2s — 집계 뷰 인덱스로 확보, 초과 시 사전 집계 테이블로 승격.

## 5. API 스케치

```
/analytics/dashboard       GET (위젯별 데이터 일괄)
/analytics/sales           GET ?group_by=partner|item|period
/analytics/purchases       GET
/analytics/inventory       GET
/analytics/receivables     GET ?aging=
/analytics/pnl             GET ?period=
/reports/saved             GET/POST/PATCH/DELETE, POST /{id}:run
```

## 6. 연동·이벤트

- 구독 없음 — 조회 시점 데이터로 계산. (대량 알림형 리포트는 후순위)

## 7. 수용 기준

- [ ] 대시보드 KPI 수치가 원장·수불 데이터와 일치
- [ ] 분석 리포트 그룹별 합계 = 원장 합계
- [ ] 저장 리포트 재실행 시 동일 정의로 조회

## 8. 후순위·미결

- BI 연동·데이터 추출 API, 임의 쿼리, 예측 — P2 후순위~제외

# 부록. 제외 모듈 (재검토 조건)

상용 조사에서 나왔으나 범위에서 제외한 항목. 업종·고객 요구 확정 시 재검토:

- 수출입(P/O·L/C·HS코드), 건설/서비스 업종 특화, POS·쇼핑몰 연동
- LOT/시리얼·유효기한(식품·의료), 성과·평가·인사 고도화
- 설계 방침: 업종 특화는 테넌트 기능 플래그로 나중에 켤 수 있게 코어에 훅만 유지
