# 02. 영업 모듈 설계 계획서

> 목적: 견적→수주→출고→매출→세금계산서의 판매 파이프라인 설계. 매출 확정이 재고 차감·자동분개·세금계산서를 유발하는 트리거 모듈. 수금·미수 관리는 자금 모듈 소유, 영업은 조회·링크만 제공한다.
> 우선순위: P0. 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: 견적, 수주(주문), 출고지시/확정, 매출(세금계산서 연동), 반품, 수금·미수 조회(등록은 자금 모듈), 단가 관리, 여신한도
- 제외: CRM/영업기회·AS 서비스(후순위), POS·쇼핑몰(제외), 수출입 특화(제외)

## 2. 화면/메뉴

| 메뉴 | 기능 |
|---|---|
| 견적 관리 | 견적서 입력·출력·발송, 수주 전환, 버전 |
| 수주 관리 | 수주서, 납기·잔량·마감 상태, 부분출고 허용 설정 |
| 출고 지시/확정 | 수주→출고지시(창고 작업 단위)→출고확정, 피킹 목록 |
| 매출 관리 | 매출 확정 → 세금계산서 초안 + 자동분개, 발행 대기 |
| 반품 관리 | 매출/출고 참조 반품 → 입고 복귀 + 수정계산서 |
| 수금·미수 조회 | 미수 현황 링크, 인보이스별 수금 상태 (등록·상계는 자금 모듈) |
| 단가 관리 | 거래처별 단가·최근단가·단가 이력 |
| 조회 | 수주잔량 현황, 거래처별/품목별/사원별 매출, 여신현황, 채권연령(P1) |

## 3. 데이터 모델

| 테이블 | 주요 컬럼 |
|---|---|
| `sales_quote` + `_line` | doc_no, partner_id, site_id, quote_date, valid_until, status / item, qty, price, vat_rate |
| `sales_order` + `_line` | doc_no, partner_id, site_id, order_date, due_date, status / item, qty, price, shipped_qty, closed_flag |
| `shipment` + `_line` | doc_no, order_id, warehouse_id, ship_date, status / item, qty, unit_cost(출고 확정 시 재고 모듈이 평균단가를 역주입 — 동기 호출 반환값) |
| `sales_invoice` + `_line` | doc_no, partner_id, site_id, supply_date, due_date(결제기한 = supply_date + payment_term 스냅샷), supply_amt, vat_amt, status, tax_invoice_id |
| `sales_return` + `_line` | 원 매출·출고 참조, reason |
| `receipt` | doc_no, partner_id, amount, settle_method(현금/계좌/어음/상계), bank_account_id, status — **소유: 07 자금 모듈** (조회·링크만) |
| `receipt_allocation` | receipt_id, invoice_id, amount — 소유: 07 자금 모듈 |
| `partner_price` | partner_id, item_id, partner_item_code, partner_item_name, price, effective_from (단가 이력 — 기준정보의 거래처별 품목코드 매핑을 흡수하여 단일 테이블로 통합) |

- 라인 공통: `item_id` + 스냅샷(name·spec·unit), `qty`, `unit_price`, `supply_amt`, `vat_amt`, `account_id`(매출계정), `warehouse_id`.
- 문서 간 참조 체인: quote→order→shipment→invoice→tax_invoice·journal_entry — 상세 화면에서 양방향 드릴다운.

## 4. 상태머신

```
quote:    draft → sent → ordered | expired | cancelled
order:    draft → confirmed →(부분출고 반복)→ closed | cancelled
shipment: draft → confirmed            ──▶ 재고 stock.out 이벤트
invoice:  draft → posted               ──▶ 분개 + tax_invoice 초안
return:   draft → posted               ──▶ 입고 복귀 + 수정계산서 연결
receipt:  draft → posted               ──▶ 분개 + 채권 상계
```

## 5. 분개 규칙 (posting_rule 매핑)

| 이벤트 | 차변 | 대변 |
|---|---|---|
| `sales_invoice.posted` | 외상매출금(또는 보통예금) | 제품매출 + 부가세예수금 |
| `sales_return.posted` | 제품매출(-) + 부가세예수금(-) | 외상매출금(-) |
| `receipt.posted` | 보통예금(수단별) | 외상매출금 |
| `shipment.confirmed` | (선택) 매출원가 대 재고자산 — 재고 분개 정책에 따름. 단, 매출원가는 **매출 확정 시점에 해당 매출에 대응하는 출고 수량 기준**으로 역산하는 것을 기본값으로 권장 (부분출고·월합산 시 수익·비용 대응 원칙) | |

## 6. 비즈니스 규칙·검증

- 출고 가능 수량 = min(수주잔량, 재고가용량) — 초과 출고 차단, 음수재고 허용은 테넌트 플래그.
- 여신한도: 수주·출고·매출 단계 중 선택 지점에서 `미수 + 당건 ≤ credit_limit` 검사 — 경고(기본)/차단(설정).
- 단가: 라인 입력 시 `partner_price` 최신 유효 단가 자동 제안, 없으면 `item.sale_price`, 직접 수정 가능(이력 남김).
- 반올림: 라인별 `vat = round(supply × 0.1)` 후 합계 — 세금계산서와 동일 규칙.
- 수주 마감: 전 라인 출고 완료 시 자동 closed, 미출고 잔량은 사용자가 마감 처리.

## 7. API 스케치

```
/sales/quotes   /sales/orders   /sales/shipments   /sales/invoices   /sales/returns
POST /sales/orders/{id}:ship                    # 수주→출고지시 생성
POST /sales/invoices/{id}:issue-tax             # 세금계산서 발행
GET  /sales/orders/{id}/progress                # 수주 잔량·출고 현황
GET  /sales/partners/{id}/receivables           # 거래처 채권·미수
/sales/partner-prices
# 수금 등록·상계는 자금 모듈 API — /finance/receipts (07)
```

## 8. 연동·이벤트

- 발행: `shipment.confirmed` → 재고 차감(**동기**, 확정 트랜잭션 내 — 00 §2), `sales_invoice.posted` → 분개+세금계산서 초안(비동기), `receipt.posted` → 분개+상계(비동기, 자금 모듈 소유)
- 구독: `tax_invoice.state_changed` → 매출 화면 상태 배지 갱신
- 외부: 세금계산서 연계 사업자(06 모듈 경유), 인쇄 양식(견적서·거래명세서·출고지시서)

## 9. 수용 기준

- [ ] 견적→수주→출고→매출→세금계산서 종단 흐름 완주 (수금·상계는 자금 모듈과 연계 확인)
- [ ] 부분출고 시 잔량 정확, 초과 출고 차단
- [ ] 매출 posted 시 분개 + 세금계산서 초안 생성 (posting_rule 설정 변경 시 반영)
- [ ] 반품이 수정계산서·입고 복귀로 연결
- [ ] 거래명세서·견적서 PDF 출력
