# 03. 구매 모듈 설계 계획서

> 목적: 구매요청→발주→입고(검수)→매입→지급의 구매 파이프라인 설계. 영업의 대칭 구조로 같은 문서 프레임워크·분개 엔진을 공유한다.
> 우선순위: P0. 공통 프레임워크는 [00_공통_설계기반.md](00_공통_설계기반.md) 참조.

---

## 1. 범위

- 포함: 구매요청, 발주, 입고·검수, 매입(매입 세금계산서 수집 연동), 매입반품, 지급(P1), 매입처 단가
- 제외: 외주 가공(P2 생산), 수입 특화(제외)

## 2. 화면/메뉴

| 메뉴 | 기능 |
|---|---|
| 구매요청 | 부서별 요청→발주 전환 (P1; P0은 발주 직접 생성 허용) |
| 발주 관리 | 발주서 입력·출력·발송, 입고 잔량·마감 |
| 입고 관리 | 입고 등록, 검수수량·불량수량 분리, 부분입고 |
| 매입 관리 | 매입 확정 → 자동분개, 매입 세금계산서 매칭 |
| 매입반품 | 입고/매입 참조 반품 → 출고 + 수정계산서 수신 |
| 지급 관리 | 지급 등록·인보이스 상계·미지급 현황 (P1) |
| 조회 | 발주잔량, 매입처별/품목별 매입, 미지급 현황, 채무연령(P1) |

## 3. 데이터 모델

| 테이블 | 주요 컬럼 |
|---|---|
| `purchase_request` + `_line` | doc_no, dept_id, requester, need_date, status (P1) |
| `purchase_order` + `_line` | doc_no, partner_id, site_id, order_date, due_date, status / item, qty, price, received_qty |
| `goods_receipt` + `_line` | doc_no, po_id, warehouse_id, receive_date / item, qty, inspect_qty, defect_qty, status |
| `purchase_invoice` + `_line` | doc_no, partner_id, site_id, supply_date, supply_amt, vat_amt, status, collect_source(tax_api/manual), tax_invoice_id |
| `purchase_return` + `_line` | 원 입고/매입 참조, reason |
| `payment` | doc_no, partner_id, amount, settle_method, bank_account_id (P1) |
| `payment_allocation` | payment_id, invoice_id, amount |
| `vendor_price` | partner_id, item_id, price, effective_from |

## 4. 상태머신

```
request:  draft → requested → ordered | cancelled          (P1)
po:       draft → confirmed →(부분입고 반복)→ closed | cancelled
receipt:  draft → confirmed ──▶ stock.in 이벤트 (검수수량만 재고 반영, 불량은 별도)
invoice:  draft → posted    ──▶ 분개 + 매입계산서 수집 매칭
return:   draft → posted    ──▶ stock.out + 분개
payment:  draft → posted    ──▶ 분개 + 채무 상계
```

## 5. 분개 규칙

| 이벤트 | 차변 | 대변 |
|---|---|---|
| `purchase_invoice.posted` | 재고자산(또는 상품매입·원재료) + 부가세대급금 | 외상매입금 |
| `purchase_return.posted` | 외상매입금(-) | 재고자산·부가세대급금(-) |
| `payment.posted` | 외상매입금 | 보통예금(수단별) |
| `goods_receipt.confirmed` | (선택) 재고자산 대 미착상품 — 입고·인보이스 시차 분개 사용 시 | |

## 6. 비즈니스 규칙·검증

- 입고 수량 ≤ 발주 잔량(초과 입고는 테넌트 설정), 부분입고 누적 `received_qty` 갱신.
- 검수: `inspect_qty`가 `qty`와 다르면 불량수량 별도 기록 — 불량은 불량창고(`wh_type=불량`) 또는 반품 대기로 처리, 정상 재고 미반영.
- 단가: `vendor_price` 최신 유효 단가 제안 → 없으면 `item.purchase_price`.
- 매입 확정은 입고와 독립 가능(미착상품 시나리오) — 분개 정책에 따라 입고 시점 또는 인보이스 시점 처리.
- 매입 세금계산서 수집분(06 모듈)과 `supply_date+partner+금액`으로 자동 매칭, 불일치는 수기.

## 7. API 스케치

```
/purchase/requests  /purchase/orders  /purchase/receipts  /purchase/invoices  /purchase/returns
POST /purchase/orders/{id}:receive               # 발주→입고 생성
POST /purchase/receipts/{id}:inspect             # 검수 확정
GET  /purchase/orders/{id}/progress              # 발주 잔량·입고 현황
GET  /purchase/partners/{id}/payables            # 거래처 채무·미지급
/purchase/payments  /purchase/vendor-prices
```

## 8. 연동·이벤트

- 발행: `goods_receipt.confirmed` → 재고 입고, `purchase_invoice.posted` → 분개, `payment.posted` → 분개+상계
- 구독: `tax_invoice_purchase.collected`(06) → 매입 매칭 대상 추가
- 외부: 매입 세금계산서 수집(06 경유), 인쇄 양식(발주서·입고지시서)

## 9. 수용 기준

- [ ] 발주→입고(검수)→매입→매입계산서 매칭 종단 흐름
- [ ] 부분입고 잔량 정확, 검수 불량은 재고 미반영
- [ ] 매입 posted 시 분개, 매입 수집분과 자동 매칭
- [ ] 발주서·입고지시서 출력

## 10. 후순위·미결

- 구매요청 승인 워크플로, 미착상품 관리 화면, 외주 발주 — P1~P2
- 미결(00 §7-6): 입고 검수를 별도 상태로 둘지 vs 입고 라인의 `inspect_qty`로 간소화 — 간소화 권장.
